## 一、五维审计尺 · 完整判据

### 维度① 情景对齐（最高优先，最隐蔽）
**尺子**：报告得出的结论，与它推荐你去执行的动作，是否处在同一个「情景」下？

识别模式：
- 收口/关键数字表基于**情景 A**（如「继续自缴 13 年」）算出差额与成本，据此给结论「选 X 省钱」。
- 但「一句话行动」执行的是**情景 B**（如「2034 后养老停缴」）。
- 一旦按情景 B：支撑结论的量化理由（那笔自缴成本）**根本不发生** → 结论前提蒸发。

判定话术：「要么结论作废（因为实际不这么执行），要么补一版情景 B 下的对照测算。当前收口页把两个情景的结论焊在了一起。」

修复：新增「情景 B 下 A地领 vs B地领」对照表；把情景 A 的数字降级为 `<details>` 折叠的「对照情景」保留不删；在「被证伪旧结论」清单补一条「情景错配」。

### 维度② 假设支撑
**尺子**：关键假设有没有一手数据支撑？是否与报告自身其它节自相矛盾？

识别模式：某节直接取「历史平均指数 = 2.0」，另一节自陈「早期工资低、指数大概率 < 1」——两节互斥且无缴费明细。
后果分级：对**差额**影响小（已被敏感性表覆盖），但决定**绝对量级**（若真实指数~1.3，绝对养老金低一大截）。
修复：绝对数下方加 ⚠️ 标注「依赖 XX 假设、与 YY 节矛盾、无明细支撑；只有差额稳健，绝对值不可当真实预期」；待核实新增「查实际缴费明细校准」。

### 维度③ 口径一致
三查：
1. **名义值 vs 现值（折今日）** 是否混用。
2. **旧数残留**：改了表内数（47→77），结论文字里旧值未同步。
3. **优势项被折扣抹平**：名义优势（门诊比例、费率）忽略了异地/条件下调。真实比较应是「A地参保→在B地异地报销（比例未知、大概率更低）」对「B地本地」，名义 22pt 差距可能被抹平甚至反超。
修复：把「决策主依据」从会被折扣的名义优势，改挂**不受异地折扣影响的硬资格**（如本地缴满 N 年锁定终身医保退休免缴资格）。

### 维度④ 可复现性
先查仓库有无配套脚本（`Glob **/*.py`、grep 养老金/测算关键词）。常发现：**测算数无脚本源**（其它 .py 都是别的领域，如资产/现金流审计，与养老公式无关）。
如实报告「无可复现计算源，仅能就文本公式逻辑审计，改数无法复核只能信任」。建议把测算固化为脚本入库，与既有审计脚本同目录风格。

### 维度⑤ 优先级排序
**尺子**：全文证据最强的一层，是否恰好落在真正的决策变量上？
典型错位：报告正确判定「养老差是噪声」，于是唯一实体决策落到「医保」，偏偏医保这层证据最弱（费率待核、异地未算）——优先级反了。
修复：把决策理由从最弱证据层，改挂到该层里最硬的资格性事实；或诚实说明该决策量级本就不大。

### 收尾必点：真实决策量级在哪一层
审计最后要给一句「净判断」：把报告纠结的量级与更高量级的人生变量对齐。例：「再干 8 年到 2034 vs 2031 就走」净差约 45 万，是全部社保差异（77 元/月）的几十倍——**这是人生题不是社保题**。

## 二、命令模板（PowerShell 5.1 / Windows）

> 无 `&&`，用 `;` 与 `if ($?)`。所有文件路径含中文/空格一律 `-LiteralPath` + 双引号。

**A. 定位可复现脚本**
```powershell
# 在 SKILL/仓库根用 Glob 工具找 *.py，再 Grep 关键词(养老金|测算|pension)确认相关性
```

**B. 拷贝工作副本到 outputs（不动 git 源）**
```powershell
Copy-Item -LiteralPath "C:\Users\<u>\github-repos\wiki-life\wiki\execution\<报告>.md" `
  -Destination "<workspace>\outputs\<报告>.md" -Force; if ($?) { "COPIED_OK" }
```

**C. grep 校验无旧值残留**
```powershell
$f="<workspace>\outputs\<报告>.md"; $c=Get-Content -LiteralPath $f -Encoding UTF8 -Raw
"选昆明出现次数: " + ([regex]::Matches($c,"选昆明").Count)
"总行数: " + (Get-Content -LiteralPath $f).Count
```
（控制台中文可能 GBK 乱码，**数字计数仍可信**；正文一致性用 Grep 工具按 pattern 核对。）

**D. 写回源文件（仅在用户明确指令后）**
```powershell
Copy-Item -LiteralPath "<workspace>\outputs\<报告>.md" `
  -Destination "C:\Users\<u>\github-repos\wiki-life\wiki\execution\<报告>.md" -Force; if ($?) { "COPIED_OK" }
git status --short   # 确认仅目标文件 M
```

**E. commit（用户给提交信息后；逐个 add，中文加引号，不用 -A）**
```powershell
git add "wiki/execution/<报告>.md"
git commit -m "<用户指定信息>"
git log -1 --stat   # 肉眼核对中文正常、无乱码/BOM、仅该文件变更
```

**F. push（需再次单独确认；代理未开降级直连）**
```powershell
git push origin master 2>&1; if ($LASTEXITCODE -ne 0) { "--- 直连重试 ---"; git -c http.proxy="" -c https.proxy="" push origin master 2>&1 }
git status -sb; git log origin/master -1 --oneline   # 确认与远端齐平
```
- PowerShell 把 git 的 stderr 进度输出渲染成红字是**假报错**，以结果行 `xxxxx..yyyyy master -> master` 为准。

## 三、校准案例 · 2026 社保参保地选择（北京/杭州/昆明）

**背景**：用户 1984 年生、2006-07 参加工作；单位允许每年在京/杭/昆三地自由选参保地，按实际工资申报（年收入约 30 万），大概率不在杭州居住。报告历经 v1→v2→v3 三次推翻、一次全面审计、五轮前提变更。

**五维实审结论（Phase A）**：
1. ①情景对齐（致命）：TL;DR 用「继续自缴 13 年」表（23,545/23,468，含 13 年自缴带来的 +13% 基础养老金与入账户额）得「选昆明省 2.8 万」，但行动走「养老停缴」→ 停缴后两城个人账户相同、2.8 万成本不发生，「选昆明」前提蒸发。且「停缴留杭州领 vs 停缴转回昆明领」这一对被实际执行的选择，全篇从未对比。
2. ②假设支撑：历史平均指数=2.0（某节）与「早期指数大概率<1」（另一节）自相矛盾、无缴费明细支撑。差额 77 元稳健，绝对养老金水平当不了真预期。
3. ③口径：门诊 82% 优势忽略异地就医下浮（人住昆明）→ 22pt 名义差可能被抹平；应改挂杭政函88号(八) 杭州医保退休免缴资格（本地 10 年 + 累计 20 年，不受异地折扣影响）。
4. ④可复现性：仓库无社保测算脚本（retire-audit/*.py 均为资产/现金流审计），数字无计算源。
5. ⑤优先级：养老差是噪声（判对），唯一实体决策落医保，偏偏医保层证据最弱（费率待核、异地未算），优先级反了。
- 顺带内部矛盾：页首前提「再工作 5 年→2031」与正文「8 年→2034」打架；正文残留「差 47 元(0.19%)」而表内已改 77。

**v4 情景对齐收口（Phase B 修订）**：TL;DR 整块改为执行情景=养老停缴，新增「停缴·留杭州领 vs 转回昆明领」对照，点明 2.8 万不发生、留杭州真正理由是非钱的三件事（少办一次跨省转移 + 规避云南医保退休本地年限未确认 + 锁定杭州医保退休免缴资格）；原自缴表降级为 `<details>` 折叠对照情景；被证伪旧结论扩为四条（新增「选昆明省2.8万=情景错配」）；50 岁临时账户卡点厘清为「留杭州不转出即不触发」。过程留痕区原样保留。写回 +56/−32，commit `社保结论与最佳行动方案`。

**固定收尾三件套（示例形态）**：
- 一段话结论：把「选杭州还是昆明」当社保题是伪命题（差 77 元/月 0.33%，且是未采用情景的数）；真正留杭州理由是三件非钱的事；决策量级在「再干到 2034 vs 2031」约 45 万，是社保差异几十倍。
- 最佳行动方案：干到 2034，在职每年锁杭州不断缴；2034 离职养老停缴、关系留杭州封存计息、不转移，2047 杭州退休；医保杭州续缴至 2047。执行前确认两点：①杭州社保能否出具「养老关系存续」书面凭证；②若还在犹豫转回昆明才需向云南医保确认退休本地年限。
- 待核实清单：杭州养老关系存续书面凭证、云南医保退休本地年限(10 还是 15 年)、昆明灵活就业费率、查缴费明细校准历史指数。
