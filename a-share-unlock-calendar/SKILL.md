# A股限售解禁日历

用东方财富数据中心"限售解禁"表（reportName=RPT_LIFT_STAGE，免费、无需 token）按股票代码批量获取未来解禁事件，输出按日期排序的解禁日历表，并接回用户持仓/估值窗口给出筹码供给（抛压）提示。

## 禁止事项

- 禁止把"解禁日"等同于"必砸盘"——实际减持受减持新规约束（控股股东/实控人破发破净限制、90 天预披露），必须注明这一点
- 禁止给出买卖投资建议——仅呈现解禁数据与筹码供给结构分析
- 禁止用本接口查询港股、美股或未上市公司——港股（如基石投资者 6 个月锁定）此接口取不到，必须明确告知用户需另行处理；未上市公司（如长鑫存储类情形）直接说明不适用
- 禁止对 A+H 双重上市标的张冠李戴——用户持有 H 股时，A 股（如科创板/主板代码）的定增/首发解禁不构成其直接抛压，需从日历中摘除并说明（如中芯国际持 H 案例）
- 禁止捏造解禁记录——接口窗口内返回为空就写"无未来解禁记录"（并注明可能是首发限售已全流通）
- 禁止硬编码"今日"日期——执行前必须 `date` 取真实系统日期

## 强制要求

- 结果必须标注数据源（东方财富数据中心 RPT_LIFT_STAGE）与抓取时间
- 单位必须换算后再展示：LIFT_MARKET_CAP 单位是**万元**（÷10000 → 亿元）；CURRENT_FREE_SHARES / ABLE_FREE_SHARES 单位是**万股**；FREE_RATIO / TOTAL_RATIO 原始值是**小数**（×100 → 百分数；脚本输出的 *_pct 字段已换算好，直接用）
- 多代码批量查询必须走脚本输出 **UTF-8 JSON 文件**，再用 Read 工具读取——禁止直接靠 curl stdout 判断中文（Git Bash GBK 乱码坑）
- 时间窗过滤在服务端拿全量后**客户端**执行：仅保留 `FREE_DATE ≥ 今日` 且落在窗口内（默认 12 个月，用户可要求 24 个月）
- 大规模解禁必须显著标出（表格加粗），参考阈值：解禁市值 ≥ 100 亿 或 相对现流通盘 ≥ 100% 或 占总股本 ≥ 20%；小解禁（如占总股本 <1% 的股权激励零头）可合并列示但须注明省略行数

## 工作流

```
用户输入（股票代码 / "我的持仓" / 时间窗）
      |
      v
Phase 1  确定标的与时间窗（date 取今日；持仓→复用 a-stock-realtime）
      |
      v
Phase 2  批量抓取（scripts/unlock.py → UTF-8 JSON）
      |
      v
Phase 3  日历表格输出（按日期排序，大解禁加粗，单位换算）
      |
      v
Phase 4  抛压提示（可选：接回持仓/兑现窗口，分"日历型 vs 持续型"供给）
```

## Phase 1 — 确定标的与时间窗

1. 执行 `date "+%Y-%m-%d"` 获取今日（时区 Asia/Shanghai）。
2. 标的来源：
   - 用户直接给 6 位代码（沪 6 开头 / 深 0、3 开头 / 北交所 8、4 开头）；
   - 用户说"我的持仓" → 复用 a-stock-realtime 的持仓数据（`uv run {baseDir}/../a-stock-realtime/scripts/portfolio.py show` 或直接读其 portfolio.json），取其中 A 股代码；
   - 用户给股票名称 → 要求确认 6 位代码，不猜。
3. 时间窗默认未来 12 个月；用户提到"估值扩张窗口/兑现计划"等可放宽到 24 个月并在输出中说明。
4. A+H 双重上市标的：先问清（或从上下文确认）用户持有 A 还是 H；持 H 则该标的的 A 股解禁仅作间接传导说明，不计入其个人抛压日历。

## Phase 2 — 批量抓取

**首选脚本（推荐）：**

```bash
uv run {baseDir}/scripts/unlock.py 688041 688981 688702 --months 24 --out lift_out.json
```

- 脚本用标准库 urllib，无第三方依赖；stdout 只打印 ASCII 日志与行数，中文数据全在 UTF-8 JSON 里，**用 Read 工具读 lift_out.json**。
- 单只快速探查也可用 curl（注意 filter 中 `=` 和 `"` 需编码为 `%3D`、`%22`）：

```bash
curl -s "https://datacenter-web.eastmoney.com/api/data/v1/get?sortColumns=FREE_DATE&sortTypes=1&pageSize=50&pageNumber=1&reportName=RPT_LIFT_STAGE&columns=ALL&filter=(SECURITY_CODE%3D%22688041%22)" -H "User-Agent: Mozilla/5.0" -H "Referer: https://data.eastmoney.com/"
```

## Phase 3 — 日历表格输出

按 `free_date` 升序输出 Markdown 表，大解禁行加粗：

| 解禁日 | 标的（仓位%） | 类型 | 解禁市值 | 占总股本 | 相对现流通盘 |
|---|---|---|---|---|---|
| 2027-03-15 | **盛科通信（24%）** | 追加承诺限售 | **651.7 亿** | **49.0%** | 99% |
| 2027-04-21 | **盛合晶微（10%）** | 首发原股东+战配 | **843.5 亿** | **35.2%** | **379%** |

要点：
- "相对现流通盘" = FREE_RATIO；次新股流通盘小，该倍数比解禁市值绝对值更能反映真实抛压（379% 即解禁量是现有流通盘的 3.79 倍）。
- 解禁户数用 BATCH_HOLDER_NUM（脚本字段 holder_num），户数少+定增配售意味着套现动机集中，可在类型列括注"（N 户）"。
- 表格之外必须单独列出**窗口内无未来解禁记录的标的**（明确写"首发限售已全流通/无大规模解禁"），避免用户误以为漏查。
- 同窗多笔大额解禁叠加时，汇总一句"X 个月内合计约 N 亿解禁市值，落在仓位合计 P% 的标的上"。

## Phase 4 — 抛压提示（接回持仓/估值窗口）

按用户框架做筹码供给分析，不越界到买卖建议：

- **类型动机区分**：定增机构配售（成本低于市价、户数少、浮盈套现动机明确、不受大股东减持限制约束）＞ 首发原股东/战配（若含大股东则受减持新规压制一部分）＞ 股权激励等零头（忽略级）。
- **窗口撞车检查**：若解禁洪峰与用户既定兑现/估值扩张窗口重叠，明确指出冲突及量级，把决定权交还用户。
- **供给分类**：日历型抛压（有具体日期，可提前规避/兑现）vs 持续型抛压（H 股无锁定期日历、大基金分批减持等，无法按日管理）——两者管理手段不同，输出时分开归类。
- 结尾固定声明：解禁日≠必砸盘，数据不构成投资建议。

## 字段与单位速查表（RPT_LIFT_STAGE，columns=ALL）

| API 字段 | 含义 | 单位/坑 |
|---|---|---|
| SECURITY_CODE / SECURITY_NAME_ABBR | 代码 / 简称 | 名称含中文，只从 JSON 文件读 |
| FREE_DATE | 解禁日期 | ISO 字符串，取前 10 位比较 |
| FREE_SHARES_TYPE | 解禁类型 | 首发原股东/战配/机构配售/定增/追加承诺等 |
| CURRENT_FREE_SHARES | 本次解禁数量 | **万股** |
| ABLE_FREE_SHARES | 实际可流通数量 | 万股 |
| LIFT_MARKET_CAP | 解禁市值 | **万元**，÷10000→亿元 |
| FREE_RATIO | 解禁量/现流通盘 | **小数**（0.99=99%，×100 转百分数；可 >100%，次新盘小） |
| TOTAL_RATIO | 占总股本比例 | **小数**，同上（个别返回键名或为 TOTALSHARES_RATIO，脚本已做回退） |
| BATCH_HOLDER_NUM | 本批解禁户数 | 整数；输出表格括注"（N 户）"用此字段 |
| NEW | 解禁参考价 | 元 |

## 错误处理

| 场景 | 处理 |
|---|---|
| 接口 result 为空/null | 该标的写"窗口内无解禁记录"，不报错终止其余代码 |
| 网络超时 | 重试 1 次，仍失败则标注该代码缺失 |
| 代码非 6 位数字 | 跳过并要求用户确认 |
| uv 不可用 | `python {baseDir}/scripts/unlock.py`（无第三方依赖） |
| 窗口内全部无解禁 | 明确输出"无未来解禁"结论，勿硬凑表格 |

## 数据源

东方财富数据中心：`https://datacenter-web.eastmoney.com/api/data/v1/get`，固定参数 `reportName=RPT_LIFT_STAGE`、`sortColumns=FREE_DATE`、`columns=ALL`，filter 按 SECURITY_CODE 逐代码查询，需带 User-Agent 与 Referer 头。免费、无 token。

## 限制

- 仅 A 股（沪深）；港股/美股解禁、基石锁定不覆盖
- 不含减持预披露、大股东实际卖出节奏（那是持续型供给，需另查公告）
- 脚本按逐代码查询，一次建议 ≤10 只
- 不提供投资建议
