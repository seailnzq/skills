# 宏观/产业新闻增量分析骨架

把一条宏观或产业新闻，按本用户已接受的固定层次拆成"增量简报"。核心原则：先纠偏、再论证、后落地——答案必须每条关键数字带日期与口径，且收尾给出"并入跟踪页 + 挂核查提醒"两个动作。

## 适用与不适用

**适用**：用户抛出一条宏观/产业/政策新闻或统计数据，问"怎么看""增量在哪""对我持仓意味着什么"。典型如成品油调价公告、利率与住房数据、宏观统计发布、监管措辞变化。

**不适用（边界）**：
- FOMC 决议会后市场定价核查 → 用 `fed-rate-pricing-check`（本技能第 4 步涉及利率链时可沿用其口径与回写格式）
- 赛道/行业系统性深度研究并归档 → 用 `industry-research`
- 只负责把研究结论建综合页入库 wiki 的归档动作 → 用 `wiki-research-sync`
- 个股实时价格/分时量能/持仓盈亏 → 用 `a-stock-realtime`
- 中文卖方研报/公众号当日采集镜像取全文 → 用 `wechat-report-mirror-fetch`

## 五步流程

### 1. 前提校准（先纠偏再论证）

逐项核对用户问题里隐含或引用的数字与统计口径，任何一处偏差都要在答复第一段显式纠正，并给出正确数值 + 来源口径 + 日期。常见偏差类型见 reference.md 的「口径纠偏对照表」：
- 传闻值/情景推演 vs 实际公布值（"利率接近 8%"→ 实为 7.40%–7.50%，8% 只是情景推演）
- 发布时滞 / 数据新鲜度错配（"最新新屋销售还在涨"实为 8 月数据、9 月 24 日发布，未吸收 9 月利率冲击）
- 中位数成分效应（中位价与均价不同向 → 成交结构迁移，不能读成"同一资产降价 X%"）
- 签约 vs 交割口径（新屋"销量"记签约、成屋待签约≠已成交）
- 样本占比偏差（新屋仅占住宅交易约 15%，用其判断楼市冷暖是样本偏差，应回看成屋端）

不先校准前提就直接顺着用户数字论证 = 结论建立在错误数值上，是本骨架第一大坑。

### 2. 拆增量信息

公告/数据本身的事实量往往只有一句话（本轮不动、销量 +6.4%），价值在"相对常态变了什么"。沿三条挖：
- **措辞/机制层面的首次变化**：把标准句式与本次句式对照，找出新增的归因、新出现的定性。（例：发改委首次把"中东地缘局势复杂多变""短暂回落后又出现较大幅度上涨"写进搁浅理由，等于官方确认"这轮本该降价，被地缘反弹吃掉"）
- **与共识测算的预期差**：市场此前一致预期 vs 实际结果。（例：机构集中测算下调 220–250 元/吨，结果既没降也没涨 → "等 15 号再加油"白等）
- **日历与下一可验证时间点**：本轮在序列中的位置 + 下一次可验证日期。（例：年内第 20 次窗口、格局"十三涨五跌二搁浅"、下一窗口 10 月 29 日 24 时）

### 3. 区分易混机制类别

对同果不同因、且决定后续传导路径的分类，必须显式拆开，给判据（用词、依据条款、是否结转），不能混为一谈。详见 reference.md「易混机制类别库」。
（例：本次成品油是"机制内自然搁浅"（10 个工作日均价折算不足 50 元/吨起调线）而非"国家实施临时调控"（行政压制、部分涨幅结转下期）；但前四次调控留下的结转差额仍挂在机制里，才是国际油价回落国内也难顺畅下调的结构性原因。）

### 4. 传导链映射回持仓主线

把事件沿因果链推到用户持仓框架，分两条线（措辞按原对话固化）：
- **主链**：盈利兑现 × 估值扩张。事件如何影响标的的盈利兑现节奏与估值扩张条件。
- **第二条独立风险线**：利率 / 资金池。作为独立于产业证伪的变量单列（例：油价 → 二次通胀预期 → 联储路径收紧 → 抬高贴现率；引用 CME FedWatch 定价）。产业逻辑证伪与贴现率抬升是两回事，分开计。

传导链每一环标 [推算] 或 [待核实]，不把推测写成事实。

### 5. 收尾固定提议

每次必给两个动作：
- **并入 wiki-knowledge 对应跟踪页**：指出目标页；建页/追加正文化交回 `wiki-research-sync`，回写涉及利率时沿用 `fed-rate-pricing-check` 的格式。
- **在下一可验证事件节点前挂一条核查提醒**（cron，引用第 2 步算出的日期与 tz）。

提议给出即止，用户点头才执行；不擅自建页或建 cron。

## 输出格式范式（对话内答复骨架）

1. 一句话结论：事实量 + 真正的增量在哪
2. 前提校准段：逐条纠偏，带数值/口径/日期
3. 增量拆解：措辞首变 / 预期差 / 日历下一验证点
4. 机制类别区分（若涉及易混分类）
5. 传导链回持仓：主链 + 第二条风险线，标 [推算]/[待核实]
6. 收尾两提议：跟踪页 + 核查提醒

## 坑

- 不先校准前提就顺着用户数字论证 → 结论地基错。
- 把"机制内搁浅"读成"行政调控"（或反之）→ 误判后续下调/上涨路径。
- 中位数跌幅当"同一资产降价" → 忽略成分效应。
- 用"最新月"数据却忽略发布时滞 → 把旧状态当现状。
- 传导链里把推算写成事实 → 违反数据导向。
- 收尾只分析不给两个落地动作 → 不符合本用户已接受的约定。
- qwenwork_web_search 单条 query ≤70 字符，超长报 validation failed，拆开或缩短。

## 验证

- 用户问题里出现的每个数字都在第 1 步被核对并给出正确值/口径/日期。
- 第 2 步三条增量（措辞首变 / 预期差 / 日历下一验证点）齐备，缺项显式说明。
- 第 4 步传导链每一环 [推算]/[待核实] 标注齐全。
- 第 5 步两个提议（跟踪页 + 核查提醒）已明确给出。
